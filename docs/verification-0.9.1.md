# 0.9.1 旧把手清理与侧栏开关

## 目的与根因

本次只修正工作台入口和关闭行为，保留本机 OCR、精确匹配、人工核对与不自动提交规则。

0.9.0 停止了默认创建悬浮条，但有两个遗漏：旧版 DOM 残留没有清理，截图失败仍会发送 SHELF_ERROR 并创建图片架。快捷键则只调用 open，没有关闭分支。

## 修正

- 安装/升级后尝试连接已有已授权网页；接收器初始化和启用时清理无当前实例管理的旧图片架 DOM。不申请新权限。重新加载扩展后刷新旧网页，彻底移除旧版失效脚本。
- 截图失败使用原有插件徽标和错误返回，不请求图片架；兼容错误消息也不再凭空创建悬浮条。
- Alt+Shift+F 根据窗口实际打开/关闭状态切换；截图松手仍仅打开。状态按窗口保存，后台重启恢复，并接收侧栏可见性变化；普通扩展标签页不能冒充原生侧栏报告状态。
- 增加工作台 × 按钮，等待已提交的编辑保存后关闭。独立窗口关闭自身；原生侧栏调用 close。工具栏保留浏览器原生切换行为。
- close 与 onClosed 采用官方 API，最低浏览器版本调整为 142，没有增加权限或依赖。

## 验证

修改前复现了旧 DOM 未清除、错误唤起图片架和快捷键只打开；对应测试先失败。修改后专项单元和实际扩展检查通过。2026-10-30 最终 `npm run test:regression` 退出码 0：构建、61 个单元测试及 35 组浏览器/扩展检查全部通过，完整日志另附。

原生可见侧栏检查采用 Chromium 153.0.8010.12，其余浏览器回归采用 Edge 156.0.4314.50。测试命令通过环境变量 NATIVE_PANEL_TEST_CHROMIUM 指定有界面的 Chromium；没有该变量时，普通无头检查不宣称证明原生显示与关闭。

两个现有插件目录各 62 个文件与最终 dist 逐项 SHA-256 一致；浏览器 ZIP 的 63 个文件与交付目录逐项一致。源码目录的 104 个文件与工作目录逐项一致，源码 ZIP 的 104 个文件逐项一致。manifest 确认 0.9.1、最低 142、原有 7 项权限且没有必需全站权限。本报告更新后重新同步并复核源码 ZIP。

原生侧栏开关使用有界面的 Playwright Chromium 进行真实显示/关闭上下文检查，覆盖开关循环、原生关闭后重开和多窗口状态隔离单测；命令入口采用测试钩子，仍需用户浏览器实际分配 Alt+Shift+F。Edge 自动化创建的侧栏上下文可能保持隐藏而没有原生打开事件，不能仅凭上下文存在推断已显示，因此不以该路径证明原生开关。本版额外接入页面可见性与打开成功状态报告。

官方依据：https://developer.chrome.com/docs/extensions/reference/api/sidePanel 。原生 close 从 Chrome 141 提供，onClosed 从 142 提供。没有扩展权限的旧网页不能直接清理，刷新该页后才能替换旧脚本。
