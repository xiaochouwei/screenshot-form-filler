# 0.6.5 页面与表单提示文字排查

## 复现与原因

此前空控件遮罩只遍历顶层字段，遗漏 key/value 组合内的空输入。控件旁边的说明、页面 note、ARIA 关联说明也未纳入遮罩；OCR 可以把它们拼成候选值。纯图片的混合布局补充识别只凭足够大的文字间距放行，远处的说明也可能成为值。标签内部附带的帮助文字还可能被拼入字段名。

先增加失败测试，分别复现页面说明和字段提示未遮罩、组合子项提示遗漏、远处说明误配，以及标签内帮助进入字段名，再修改生产代码。

## 通用处理

- 网页框选仍执行本机 OCR；DOM 提供排除区域，不依据具体业务字段、网址或提示句过滤。
- 空控件遮罩展开组合子字段；无明确标签的原生空输入和自带 placeholder 的 ARIA 输入仍可排除提示。
- 对控件的 `aria-describedby` / `aria-errormessage` 关联节点、页面 note/tooltip/alert、常见表单帮助和校验说明节点，排除可见文字。
- 在最近具有结构标签与控件的局部字段容器内，排除控件和标签之外的文字。只对文字行范围遮罩，不清空整个字段容器。
- 保留实际输入、已选选项和字段标签；真实输入与提示文字相同也保留。没有表单结构证据的独立业务展示文字不凭内容删除。
- 原生标签内有明确帮助标记或 ARIA 说明关联时，帮助不参与标签文本和来源证据范围。
- 纯图片的无边框补充行还必须符合已有控件的列结构或受限的控件内部区域，不再只因间距大就当作填写值。

页面使用错误或缺失的语义、封闭 Shadow DOM、Canvas，或图片中提示与真实内容视觉相同时，无法保证自动区分。不能将所有中文长句、灰色字、含“参数”的文本都当成提示。已被写进真实 value 的说明仍是实际值，需要先修正来源。纯图片识别仍须核对，不承诺所有提示都能由像素自动排除。

## 验证

- `tests/hints-capture.mjs`：任意说明文字、页面 note、ARIA 跨容器说明、多控件无独立标签、空组合子项、开放 Shadow DOM、标签内帮助，以及相同真实输入的保护。
- `tests/hints-image.mjs`：生成与业务无关的带页面说明、多输入参数行、字段帮助的表单；离线 OCR 只留下路径与备注，原始 OCR 中不含提示；与帮助相同的真实值保留，再写入新表单，参数保持空白。
- `tests/core.test.mjs`：远处说明不成为补充值，原有可辨认的无边框混合布局仍保留。
- 字数计数测试更新为在有明确字段结构时排除所有非值文字，同时保留输入内的真实分数；独立计数校验继续适用于其他结构。
- 回归入口 `npm run test:regression` 包含上述测试及既有 OCR、下拉、多选、状态、拖拽、持久化、权限与窄窗口检查。

2026-10-28 本机 Edge 完整回归通过：46 个单元测试、28 组浏览器/扩展检查。边界复查另增“提示容器内含真实控件”的保护测试，5 个提示几何用例全部通过；最终构建重新检查提示截图 OCR 与填写、标签扫描、状态框选链路。测试范围不等于用户真实网站已经现场验证。

测试使用本机 Edge 和构造页面，没有获取用户业务网站的真实 HTML。用户附件包含旧插件窗口和标注，曾另行运行真实 OCR 观察混入现象；不把该诊断图片作为准确的来源截图，亦不将其打包。
