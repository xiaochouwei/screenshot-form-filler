# 0.6.3 开关与正则勾选排查

用户反馈：从来源网页按 Alt+Shift+S 框选后，命中后继续匹配的开关和规则中的正则表达式勾选未能同步。

## 已复现的问题

1. 来源字段的证据边界包含整块布局容器。开关标签、复选框 label 或组合字段容器宽于实际内容时，框选虽然包含所有可见文字和控件，却未包含容器空白，状态记录就会被过滤掉。
2. 规则中的 key/value 已填写后，即使与来源逐字相同，旧逻辑仍将整组视为占用，连带阻止正则勾选同步。

复现与修复验证采用带宽标签容器、隐藏原生 checkbox、自定义开关和内嵌正则勾选的通用测试 DOM；没有获取或操作用户业务网站的真实 DOM，不能把复现场景通过等同于该业务网站已现场验证。

## 处理方式

- 按实际标签文字的行矩形、状态图形与子控件计算证据边界，剔除布局空白。仍要求控件、全部标签文字都在选区内。
- 状态继续从截图对应的来源网页 DOM 中读取，不通过截图颜色猜测勾选状态。
- 仅当来源组内含明确布尔状态、用户启用状态同步、目标原文字逐字一致时，保留已有文字并同步勾选。文字不同、标签重复、禁用、只读、未确认或页面变化仍拒绝。
- 对文字相等的比较发生在网页内部，仅将相等事实用于计划；不把目标现有文字值传回面板。
- 填写前重新比对原值。预览之后，即使控件占用状态没变，但实际文字变化，也不会勾选到另一条规则上。

## 测试入口

`npm run test:states` 验证三项浏览器边界和快捷键框选的完整流程：截掉布局空白后保留两个状态，本地离线 OCR、核对来源、状态同步默认关闭、一键填入和受信任拖放、原文字不重写、读回校验、不提交，以及窄窗口无横向溢出。

`npm run test:regression` 继续覆盖所有单元测试和 24 组浏览器/扩展回归。

2026-10-28 本机 Edge 验证结果：43 个单元测试和 24 组浏览器/扩展检查通过。新增的三个状态边界用例均先复现失败再修复；框选流程测试覆盖一键填入和受信任落点拖拽。最后的标签边界保护改动重新构建后，再运行标签、组合字段、跨窗口拖拽及状态框选链路，确认交付构建包含该改动。

## 更新后操作

关闭旧插件窗口，在扩展管理页重新加载，确认版本 0.6.3，再刷新来源和目标网页。在来源网页重新按 Alt+Shift+S 框选完整的标签与控件，检查列表中的开关项和“匹配规则”子项里的正则勾选，再启用“同步开关 / 勾选状态”执行填写。

旧截图没有保存的网页状态无法事后还原，单击旧记录的“识别”不会重新读取来源网页。纯图片输入的布尔状态仍需人工确认。
