# 0.7.2 下拉框等待与归属检查

## 问题与修改

用户截图显示其他 5 项填写成功，Prometheus 被跳过，原因为“无法确定下拉选项归属”。截图可以确定失败发生在下拉框操作阶段，不能单独证明该业务页面的具体触发原因。

检查 0.7.1 代码后，已用本机浏览器复现：选项面板延迟 800 毫秒出现、选项延迟 1400 毫秒返回、先返回 A 再返回目标 B、面板标为加载中却过早选择，以及已展开但缺少关联信息的菜单仍被点击。新增 5 个用例在修改前全部失败，修改后通过。

0.7.2 对展开面板最多等待约 2.5 秒，对完整目标选项另等待最多约 3 秒；等待期间不反复点击触发器。面板需连续观察到同一个候选，选项需连续观察到相同列表且满足完整精确匹配，`aria-busy` 标为加载中时继续等待。不会因为面板已有少量选项就立即判断目标选项缺失。

等待期间检查控件可写状态、类型、既有值、页面地址及面板归属；禁用、只读、隐藏、跳转或归属变化时停止。明确关联且已经展开的面板直接使用，不再次点击；已展开但没有足够归属证据时提示收起重试。多个面板、未展开、展开超时及选项等待超时给出不同原因。

完整字段和选项精确匹配、已有内容保护、人工取消保留、状态同步显式开启及不自动提交的规则继续保留。本次不增加权限、依赖、云端服务或网站专用字段分支。

## 专项验证

`tests/control-boundaries.mjs` 共 20 项，在本机 Microsoft Edge 中验证：

- 延迟单选和多选、面板延迟出现、选项延迟或分批返回、显式加载状态结束后才选择。
- 等待期间只点击一次展开触发器；明确关联的已展开外层面板不重复点击。
- 已展开但无关联证据时不猜测归属，并给出收起提示。
- 等待期间禁用、修改面板引用或同页导航后不选择。
- 多选缺少任何一项时不选择可用子集；未展开控件超时有明确提示。
- 选择后禁用、只读、隐藏或出现意外选中项，均停止后续选择。
- 原有标签引用、禁用容器和禁用原生子输入保护。

修改后的专项命令退出码为 0，20 项全部通过。

## 边界

使用通用构造测试页面进行浏览器验证，没有进入用户的实际业务页面，不能承诺截图中的特定组件已现场修复。等待上限可以覆盖本次复现的延迟，不代表任何网络耗时都能等待成功。没有加载标记时，只能判断可观察到的短暂稳定状态，不能预知未来还会追加选项。

无法建立归属关系、虚拟列表尚未渲染目标项、需要搜索或特殊鼠标事件才能展开的控件仍可能跳过。不会通过放宽精确匹配规则、点击不明面板或反复切换菜单来强行填写。
