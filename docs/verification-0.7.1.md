# 0.7.1 动态增项与多选验证

## 本次行为

继续使用浏览器扩展和本机 OCR，不新增权限、云端服务或 Windows 客户端。

图片架及字段核对窗口新增“允许增项”，默认关闭，不跨页面保存。开启后，仅调用所选表单内可唯一识别的既有添加入口。本版支持明确 key/value 子项的组合行；来源须已确认，字段名须完全一致。按钮需包含“添加/新增/增加 + 完整字段名”或“Add + 完整字段名”，或以 `aria-controls` 明确指向同名区域。没有足够关联证据的加号按钮跳过。

预览不点击按钮。正式填写时重新检查页面、表单和按钮身份，每个入口只点击一次，最多补建 5 个不同名称的行；确认新增控件唯一、完整且稳定后才填写并读回校验。已有同名行、来源重名、禁用、提交/重置控件、弹窗、跳转、创建超时或结构不符都会跳过或停止。不会向网站凭空注入业务组件，也不自动提交。

多选识别记录区分布局待核对和人工取消：只有清晰、无冲突、仅因多行布局待确认的来源，且字段和所有选项完整、唯一匹配时，才自动勾选参与填写并保存。懒加载选项在明确的填写操作中核对，全部通过才开始选择。人工取消、低可信、冲突、缺项或歧义不自动勾选。旧截图没有取消原因记录，保持原状态，重新截图或识别后可使用新规则。

## 验证内容

- 动态增项关闭时不添加；预览不添加；按钮填写、图片架真实鼠标拖拽、核对窗口填写均覆盖新增组合行和完整 key/value 结果。
- 正确表单归属、空表单入口、明确区域关联、重复填写不重复添加、来源重名或未确认时不添加。
- 同名多个按钮、禁用按钮、提交/重置输入伪装按钮、嵌套原生按钮和 label 激活均拒绝。
- 异步创建、无新行超时、页面跳转、入口变化、原生弹窗、最多 5 个增项的限制。
- 原生、iView、Element、Ant 多选，含延迟加载选项；缺失或歧义时不部分选择，既有选项不覆盖。
- 外部 PNG 实际本机 OCR 到懒加载多选填写，不手动勾选识别结果；自动确认保存至历史，人工取消跨图片架和核对窗口恢复仍有效。
- 原有图片架、封闭 Shadow DOM 坐标拖拽、离线识别、权限撤销、提示词排除及已有控件回归。
- 检查动态增项结果、图片架、核对窗口和 390 像素窄窗口截图。图片架截图中的一项跳过来自第二次填写时已完成的多选，新增行两个值均填写完成。

## 支持边界

验证使用本机 Microsoft Edge 和通用构造页面，不能代表所有业务系统均已现场覆盖；没有按网址或业务字段编写专用分支。对无法建立明确关联的动态组件跳过，不承诺任意页面均可自动增项。

调用添加后若页面响应不符，可能留下空白行，需要人工检查。插件不重试点击、不自动删除或回滚；网站本身可能在添加或填写时自动保存。

浏览器内完整鼠标拖拽已验证，不冒充 Windows 物理跨窗口、跨屏实测。浏览器外截图需系统截图后粘贴或导入。纯图片无法保证区分所有视觉相同的提示词与真实值。Canvas 表单、目标封闭 Shadow DOM、跨域嵌入及未知自定义控件不保证支持。
