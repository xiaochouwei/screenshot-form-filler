# 0.8.0 通用扫描与来源证据验证

## 目的与复盘

产品仍是浏览器插件：任意来源截图进入本机 OCR，来源网页只提供绑定本次截图的辅助证据，目标限定浏览器表单。字段及选项完全匹配且唯一才填写；保护已有值、保留人工取消、不自动提交。

此前的问题不是某个业务字段应增加一个特例，而是共同流程中有三个缺口：扫描清单与可写能力没有充分分开，OCR 的视觉折行与网页真实换行混为冲突，“参与填写”与“内容已核对”共用一个标记。因此本次从这三层修正，不增加网站地址、业务字段名或截图坐标规则。项目 AGENTS.md 保存了以后修改前需复盘目的、复现根因和明确验证证据的要求。

## 实现

- 统一记录 selected、review 和兼容旧数据的 confirmed。新识别记录默认参与；pending/conflict 不因打勾而获得写入资格。明确采用截图、网页原值或确认编辑值后才通过内容核对。旧记录及人工取消保持原状。
- 本机 OCR 继续作为主要入口。对原生文本域取得有限、可验证的折行证据；镜像测量遵循来源控件的实际计算样式、宽度和字体，忽略不支持的排版。仅验证过的自动折行可以消除假冲突，保留 imageValue；真实换行、标点、空格、字符及截断差异仍需人工选择。
- 清单覆盖原生控件、已有 HTML/ARIA、iView、Element、Ant 适配器及开放 Shadow DOM。可发现而无安全写入适配的语义控件单列原因；不将内部输入框误当作可以绕过外层语义的独立写入入口。相邻动作按钮不再使普通输入框失去明确标签。
- 扫描比较字段快照并检查可见 aria-busy，等待短暂稳定，最长约 1.5 秒。加载标记位于表单外、表单尚未渲染时也等待。超时未稳定可展示清单，但不能授权填写。撤销授权或发起新扫描使之前的异步扫描失效。
- 计数区分当前表单、全页逻辑字段、原始候选节点、组合子项、已适配/未适配、无标签及未扫描的 iframe。选择目标表单不会把局部数量伪装成全页数量。
- 核对界面显示实际的替代文字、数组、开关和组合子项值；参与复选框、核对状态、采用来源操作分别显示。图片架、拖拽、按钮填写、多选自动校验和动态增项共用参与/核对规则。

## 专项证据

新增 5 个行状态单元测试，以及 text-layout-browser、scan-coverage-browser、evidence-editor 三组浏览器检查。

- 证明默认参与并不批准不确定内容，选择证据不恢复人工取消，旧 confirmed 不能覆盖明确的新状态。
- 证明原生软折行、中英文文字、长代码及标点可按测量证据校对；硬换行、字面空格和截断仍受到保护。
- 修改前复现 CSS white-space:pre 的水平滚动被误测为折行；修改后无虚构折行。隐藏测量节点在结束后清理。
- 修改前复现撤销后立即重新授权使旧扫描复活；修改后旧扫描被拒绝，新扫描正常。
- 修改前复现先加载后出现表单时返回空清单；修改后能等待可见的表单外加载标记结束，发现新控件。
- 检查语义控件含内部原生输入时只出现一个不可写代表，邻近动作按钮、开放 Shadow DOM、无标签歧义、内嵌页面缺口与计数。
- 实际加载扩展验证默认勾选、冲突对照、显式核对、状态/组合替代值、编辑后的阻止写入、恢复人工取消、当前/全页计数及不提交。检查桌面与 390 像素窄窗口截图和横向溢出。
- 原有动态增项检查增加 selected:false 或 review:conflict 搭配过期 confirmed:true 的拒绝用例，防止核对状态被旧标记绕过。
- 完整回归中发现字符计数测试注入脚本后依赖后台另一次事件自动打开图片架，曾在等待图片架时超时。该测试改为显式发送 SHOW_SHELF 后再截图；专项重新通过，不更改产品识别或写入逻辑。

## 适用边界

验证采用不同标签、布局与组件结构构造页面，没有登录用户实际业务系统。通用意味着共用证据模型和结构规则，不代表所有网站组件都能可靠读写。

没有可靠语义和归属的自定义控件、尚未渲染的虚拟项目、iframe 内部、封闭 Shadow DOM、Canvas、富文本等仍可能不支持；清单会尽量列出可观察缺口。短暂稳定无法预知没有加载标记的未来更新；真正开始填写前仍重新核对目标结构并读回结果。

本次折行证据仅适用于受支持样式的原生 textarea，不是对全部控件的视觉 OCR 增强。无网页证据的外部图片和旧记录仍可能需要核对；重新框选才能采集新增的来源布局证据。纯像素无法保证区分外观相同的提示词与真实值。

拖拽继续通过浏览器真实鼠标手势测试图片架到表单。跨窗口旧测试通过 CDP 派发目标拖放事件，不能证明 Windows 物理跨窗口或双屏轨迹；实际业务页面和原生权限弹窗需在用户环境确认。本次不增加权限、依赖、云服务或桌面程序。
