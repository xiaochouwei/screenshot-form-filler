# 0.6.4 字符计数与截图拖拽排查

## 已复现的问题

- 输入框右侧计数与值处于同一行，OCR 将二者拼接。相邻表单横排时，前一个输入框的计数还可能并入后一个字段名。
- 拖拽接收端要求自定义 MIME 格式名存在，即使备用文本标记已送达，也会直接忽略。旧测试只清空自定义格式的数据，保留格式名，未覆盖格式本身丢失的分支。
- 图片拖动被接收列表中的所选网页限制，其他已连接网页无法接收。全部来源行未勾选时，图片无法拖动且缺少现场提示。

## 处理方式

网页辅助在原生输入框的单控件容器内寻找明确的字数计数元素，要求显示计数与实际 value.length 和 maxlength 一致，只遮罩计数文字范围。支持现有 iView、Element、Ant 计数结构和明确命名的字符计数节点；不遮罩任意普通分数文字。

纯截图在检测到的输入框内，仅排除远离正文、紧靠右边界且分子与正文字符数一致的尾部计数。支持 OCR 将计数分成多个词的情况。无法核实的计数保留待核对；单独的分数值、与正文相连的分数值不按计数删除。前一控件的孤立计数与下一字段名间距明显时，不把计数拼入字段名。未使用业务网址、字段名称或固定长度上限判断。

截图与网页真实值不同仍须核对，保留“采用网页原值”，选用后该项恢复勾选。不会以重新识别的方式追溯读取旧截图对应网页。已写进来源实际 value 的 `11/256` 不自动删除。

拖拽使用带固定前缀的备用文本标记，后台提前向已连接的具体文档发送短期就绪提示。格式丢失时，接收端仍可接受拖放；必须有可信浏览器事件，后台必须核对标记、URL、文档身份、有效期并一次性领取成功，才取得填写数据。就绪提示只含标记，不向全部接收页广播截图或字段值。普通文本拖放不能领取标记。接收列表不改变落点目标；没有已连接网页或未勾选来源字段时，按下图片显示原因。

## 验证入口

- `tests/core.test.mjs`：计数拆词、计数不符、真实分数值、相邻标签污染和标签内部空格。
- `tests/counter-capture.mjs`：来源 DOM 遮罩、真实值保留、普通说明与错误计数不遮罩。
- `tests/counter-image.mjs`：生成带计数器的干净表单，真实离线 OCR；分别验证网页辅助和无网页辅助的图片输入。
- `tests/drag-routing.test.mjs`：就绪提示不包含字段值，仍要求文档身份、标记和一次性领取。
- `tests/window-drop.mjs`：真实鼠标从截图缩略图启动拖拽，CDP 向第二浏览器窗口发送受信任落点事件；验证完全移除自定义格式后仍可填，普通文本不消费标记，未连接列表选择不禁用其他目标，填写、状态同步和窄窗口布局。
- `tests/mixed-source.mjs`：截图为主，冲突明确选用网页值后恢复参与填写。

跨窗口自动化使用 CDP 发送落点事件，未冒充 Windows 桌面上完整的物理鼠标跨窗口实测。未操作用户业务网站的真实 DOM。无法保证所有网站自定义组件都支持；既有 iframe、封闭 Shadow DOM、Canvas 等边界继续适用。

2026-10-28 本机 Edge 验证结果：`npm run test:regression` 完整通过，含 45 个单元测试与 26 组浏览器/扩展检查。最终清理无关拖放高亮的调整重新构建后，另行重跑跨窗口拖放检查通过；后台就绪提示的文档身份与最小数据测试也单独通过。用户提供的带红色标注截图另行运行真实 OCR，右侧字段标签恢复为“描述”，尾部 `18/256` 排除，正文中已有的 `11/256` 保留；该标注图的左侧输入框边界未完整检测到，不宣称恢复了该字段。用户原始图片不随包交付。

## 更新操作

关闭旧插件窗口，在扩展管理页重新加载，确认 0.6.4，然后刷新来源和目标网页，再重新框选截图。从插件中的截图缩略图拖到已连接目标网页的表单内部。系统图片文件拖到业务网页仍可能触发网页上传，不是此填表入口。
